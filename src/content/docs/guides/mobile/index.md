移动端页面设计的核心目标不是“把 `PC` 页面缩小“，而是在有限屏幕、弱网络、触控输入、低性能设备和复杂现场环境下，让用户稳定、快速、低出错地完成交互任务。

手机浏览器更偏通用消费场景，用户可能在微信、系统浏览器、`Chrome`、`Safari` 等环境中访问。`PDA` 浏览器常见于仓储、物流、巡检、门店、生产线等业务场景，通常屏幕更小、系统版本更旧、`WebView` 能力不一致，并且经常配合扫码枪、物理按键、手套操作和弱网使用。

因此，移动端页面设计应优先保证：

- 关键任务路径短
- 信息层级清晰
- 可点击区域足够大
- 网络差时可恢复
- 输入成本低
- 错误提示明确
- 页面在低端设备上也能稳定运行

这套手册用于手机移动端活字格页面的设计和评审，覆盖手机浏览器、企业微信/钉钉/飞书 `WebView`、`App` 内嵌 `H5`，以及 `PDA` 浏览器和 `PDA WebView`。

总览页只说明阅读路径和各章节分工。具体的设计步骤、模板、示例和检查清单，放在对应专题文档里，避免同一套规则在多个页面重复维护。

## 章节分工

### 目标与场景

回答“为什么做、给谁用、在哪用、怎样算完成”。

这一章用于设计开始前，明确用户、场景、设备、主流程、异常流程、中断恢复和任务成功标准。它决定后续页面结构和交互方式是否有方向。

### 信息架构

回答“先看什么、先做什么、后看什么”。

这一章用于组织页面内容，定义首屏重点、信息分组、页面结构、返回路径和上下文恢复，避免页面变成字段堆叠。

### 交互与行为

回答“怎么操作、怎么反馈、失败后怎么继续”。

这一章用于设计按钮、表单、校验、反馈、状态、错误恢复和 `PDA` 连续作业，确保用户每一步都知道系统正在发生什么。

### 视觉与感知

回答“用户能不能快速看懂并稳定判断”。

这一章用于设计首屏视觉目标、信息层级、密度、字号、状态表达、固定区域和安全区，保证小屏和 `PDA` 上仍然清楚可用。

### 性能

回答“真实设备和真实网络下是否还能稳定使用”。

这一章用于设计首屏加载、数据拆分、长列表、图片附件、交互响应、弱网恢复和真机验证，避免页面只在桌面模拟器里可用。

## 使用原则

- 先定义任务，再定义界面。页面结构要围绕任务完成，而不是围绕字段展示
- 先保证最低可用，再追求完整体验。小屏、弱网、旧 `WebView` 和连续操作场景要优先验证
- 先控制复杂度，再补充能力。移动端容错空间比桌面端更小
- 手机和 `PDA` 可以复用业务规则，但不应强行复用完全相同的交互
- 每一章都要落到模板、示例和检查清单，不只停留在原则

## 推荐基线

这些是移动端页面设计和评审时的通用参考值。具体使用方式在各专题文档中展开。

| 项目 | 推荐值 |
| --- | --- |
| 主设计宽度 | `360px` 或 `375px` |
| 最小验证宽度 | `320px` |
| `PDA` 验证宽度 | `240px`、`280px`、`320px` |
| 常规按钮高度 | 不小于 `44px` |
| `PDA` 高频按钮高度 | 不小于 `48px` |
| 正文字号 | 不小于 `14px` |
| 图标点击热区 | 不小于 `40px x 40px` |
| 相邻点击区间距 | 不小于 `8px` |

## 快速开始

开始设计或评审一个页面时，先完成下面 5 件事：

```text
1. 写清页面任务：用户在什么场景下，为了完成什么目标，需要先判断什么，再执行什么操作
2. 定义首屏判断：对象、状态、关键数值、风险提示和主操作
3. 画出行为路径：进入页面、执行操作、系统反馈、成功下一步、失败恢复
4. 确认设备边界：手机 / PDA / WebView、最小宽度、输入法、扫码、弱网
5. 准备真机验证：小屏、目标 WebView、PDA、弱网、断网和连续操作
```

如果这 5 件事还没有明确，不建议直接进入视觉稿或页面实现。
