这部分只讨论一件事：**活字格应用跑在 PDA 或 Android 设备上时，页面怎么设计才适合现场作业**。

PDA 页面不是把 PC 页面缩小，也不是做一个更精致的手机 App。它通常用在仓库、产线、门店后场、物流交接这些现场：用户边走边扫，屏幕小，网络不稳，设备可能旧，还可能戴手套、赶进度。

所以判断一个 PDA 页面好不好，不看字段放得全不全，而看它能不能做到：

- 扫码后立刻有反馈
- 首屏能看清当前任务和下一步
- 高频按钮够大，不容易误触
- 扫错、断网、提交超时后能继续
- 在真实 PDA、HAC 或目标 WebView 中不卡、不乱、不遮挡

## 一个总原则

PDA 页面要围绕“现场人员完成一条记录”设计，而不是围绕“把数据库字段都展示出来”设计。

例如收货页的主线通常是：

```text
扫描物料 -> 判断是否属于当前收货单 -> 输入数量 -> 确认收货 -> 继续扫下一条
```

页面上的字段、按钮、提示、加载策略，都应该服务这条路径。服务不了这条路径的内容，可以后置、折叠，或者放到查询页。

## 常见坑

- 直接复用 PC 表格，横向字段又多又密。
- 每扫一条都弹窗确认，连续作业被打断。
- 页面同时出现“保存、提交、确认、完成”，用户不知道点哪个。
- 扫码失败只弹“操作失败”，不保留码值，也不说明下一步。
- 弱网时没有本地暂存，提交失败后记录丢失。
- 只在电脑浏览器里看过，没有拿目标 PDA 验收。

## 开始前先确认

设计前至少把这些问题说清：

```text
谁用：仓管员、盘点员、巡检员、生产人员？
在哪用：仓库、产线、门店、户外？
用什么设备：PDA 型号、屏幕宽度、Android / WebView 版本？
跑在哪：HAC、普通浏览器，还是其他 Android 容器？
怎么输入：扫描头、摄像头扫码、物理按键、数字键盘、触屏？
一条记录怎么完成：成功后结束，还是马上进入下一条？
异常怎么恢复：扫错、重复、断网、提交超时时怎么办？
用什么验收：哪台真实 PDA，连续扫多少条，断网怎么测？
```

这些问题答不清，后面很容易做成“功能都有，但现场不好用”的页面。

## 推荐基线

| 项目 | 建议 |
| --- | --- |
| PDA 重点验证宽度 | `240px`、`280px`、`320px` |
| 高频按钮高度 | 不小于 `48px` |
| 普通按钮高度 | 不小于 `44px` |
| 图标点击热区 | 不小于 `40px x 40px` |
| 正文字号 | 不小于 `14px` |
| 相邻点击区间距 | 不小于 `8px` |
| 扫码反馈 | 收到码值后立即显示状态 |
| 连续扫码验收 | 至少连续扫码 `50` 次 |
| 弱网验收 | 断网录入、恢复后补传 |
