这套手册用于手机移动端活字格页面的落地规范，覆盖手机浏览器、企业微信/钉钉/飞书 `WebView`、`App` 内嵌 `H5`，以及 `PDA` 浏览器和 `PDA WebView`。

## 结构说明

手册主体按 5 个维度组织，而不是按单个组件拆分。这样更适合做方法论、评审标准和设计规范沉淀。

## 适用范围

- 手机业务页面：审批、查询、录入、详情、异常处理
- 企业应用 `H5`：企业微信、钉钉、飞书、`App WebView`
- `PDA` 作业页面：扫码、盘点、上架、出库、巡检、签收
- 混合设备场景：同一业务同时跑在手机和 `PDA` 上

## 使用原则

- 先定义任务，再定义界面。页面结构要围绕任务完成率，不围绕字段堆砌
- 先保证最低可用，再追求高保真。尤其要先验证小屏、弱网、旧 `WebView` 和连续操作场景
- 先控制复杂度，再补充能力。移动端容错空间比桌面端更小
- 同一业务在手机与 `PDA` 上可以复用规则，但不应强行复用完全相同的交互

## 推荐基线

| 项目 | 推荐值 |
| --- | --- |
| 主设计宽度 | 360px 或 375px |
| 最小验证宽度 | 320px |
| `PDA` 验证宽度 | 240px、280px、320px |
| 常规按钮高度 | 不小于 44px |
| `PDA` 高频按钮高度 | 不小于 48px |
| 正文字号 | 不小于 14px |
| 图标点击热区 | 不小于 40px x 40px |
| 相邻点击区间距 | 不小于 8px |

## 开始前

在开始设计或评审一个移动端页面之前，建议先把下面这份清单补齐。

### 目标定义

- 这页要解决的核心任务是什么
- 主要用户是谁么，有哪些
- 这是单次操作，还是连续高频作业

### 场景边界

- 用户在什么环境下使用，例如办公室、门店、仓库、生产线、户外
- 是否存在弱网、断网、强光、戴手套、单手操作、扫码枪输入等条件
- 是否需要兼容手机与 `PDA` 双端，或者需要多端支持

### 设备清单

- 设计基准宽度是多少？
- 最小验证宽度是多少？
- 是否需要覆盖 `PDA` 的 `240px`、`280px`、`320px` 宽度
- 目标设备型号是否已列出，例如具体手机型号、`PDA` 型号、系统版本、浏览器或 `WebView` 类型
- 是否明确最低支持版本

### 页面范围

- 这是列表页、详情页、表单页、审批页，还是连续作业页
- 页面主流程是否已确认并画出来
- 异常流程、失败流程、中断恢复流程是否已定义
- 是否有固定底栏、吸顶栏、弹层、扫码区等特殊结构

### 信息与字段

- 首屏最重要的信息是什么
- 表单字段是否分出必填、高频、低频
- 是否有金额、数量、时间、状态、异常原因等高优先级信息
- 是否存在超长文本、超长编号、复杂表格或图片上传

### 交互与反馈

- 主按钮文案和位置是否明确
- 是否需要扫码、拍照、上传、定位、签名等能力
- 提交成功后下一步是什么
- 提交失败后用户如何恢复
- 是否需要草稿、自动保存、补传、重试

### 验证与发布

- 是否已准备真机验证清单
- 是否已确认目标设备型号和测试环境
- 是否已覆盖小屏、输入法弹起、弱网、断网和低性能场景
- 是否已准备上线前验收项
