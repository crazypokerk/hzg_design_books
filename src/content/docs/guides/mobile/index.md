这部分文档只讨论一件事：**活字格应用运行在 PDA 设备上时，页面应该怎么设计才好用**。

PDA 页面和普通手机页面不一样。手机页面很多时候是“看一看、点一下、审批一下”；PDA 页面通常是在仓库、产线、门店、物流现场连续作业，用户一边走、一边扫、一边录数量，还可能遇到弱网、旧 WebView、强光、戴手套、设备卡顿。

所以 PDA 页面不要追求“像 PC 一样完整”，也不要追求“像手机 App 一样精致”。它首先要做到：

- 扫得快
- 看得清
- 点得准
- 失败后能继续
- 弱网时不丢数据
- 在真实 PDA 上不卡、不乱、不遮挡

## 一句话原则

PDA 页面要围绕“现场人员完成一条记录”来设计，而不是围绕“把数据库字段全部显示出来”来设计。

比如“PDA 收货页”的核心不是展示完整收货单，而是：

```text
仓管员扫描物料 -> 系统判断是否属于当前收货单 -> 输入数量 -> 确认收货 -> 自动准备下一次扫码
```

页面上所有内容、按钮、提示和加载策略，都应该服务这条路径。

## 最常见的错误

- 直接把 PC 页面缩小到 PDA。
- 把列表、详情、表单、历史、附件、统计都放在一个页面。
- 每扫一条都弹窗确认，用户必须反复点。
- 失败后只提示“操作失败”，不告诉用户怎么恢复。
- 扫码成功后不自动聚焦下一次输入。
- 断网后丢掉已扫记录。
- 只在电脑浏览器里看页面，不拿真实 PDA 验证。

## PDA 页面基本结构

一个常见的 PDA 连续作业页面，可以先按这个结构想：

```text
顶部：当前任务、库位、进度、网络状态
中间：扫码入口、当前物料、数量、校验结果
下方：最近一次结果、异常原因、恢复动作
底部：固定主按钮，例如“确认收货”“确认盘点”
```

不是每个页面都完全一样，但大多数仓储、物流、生产、巡检类页面都可以从这个结构开始，再按业务调整。

## 设计前先问这 10 个问题

```text
1. 谁用这个页面？
2. 在什么现场用？
3. 用什么 PDA 或 Android 设备？
4. 页面是否跑在 HAC 里？
5. 主要输入是扫码、物理按键、数字键盘还是触屏？
6. 用户每次要完成哪一条记录？
7. 成功后是结束，还是马上处理下一条？
8. 扫错、录错、重复扫时怎么办？
9. 弱网或断网时是否允许继续作业？
10. 最后用哪台真实 PDA 验收？
```

如果这 10 个问题答不清，不建议直接开始画页面或做页面。

## 推荐基线

| 项目 | 建议 |
| --- | --- |
| PDA 重点验证宽度 | `240px`、`280px`、`320px` |
| 高频按钮高度 | 不小于 `48px` |
| 普通按钮高度 | 不小于 `44px` |
| 图标点击热区 | 不小于 `40px x 40px` |
| 正文字号 | 不小于 `14px` |
| 相邻点击区间距 | 不小于 `8px` |
| 扫码反馈 | 收到码值后立即显示状态 |
| 连续扫码验收 | 至少连续扫码 `50` 次 |
| 弱网验收 | 断网录入、恢复后补传 |
