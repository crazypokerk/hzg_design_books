PDA 页面视觉设计的目标不是漂亮，而是现场人员能快速看懂、准确判断、稳定操作。

设计稿里精致的小字、浅灰色、细边框，到了仓库强光、低亮度屏幕、旧设备和手套操作场景里，可能直接失效。

![PDA 小屏视觉设计示例](../../../../assets/mobile-visual-perception.svg)

## 字号不要靠压缩字段解决

建议基线：

| 内容 | 建议 |
| --- | --- |
| 正文 | 不小于 `14px` |
| 关键数量、状态 | 可以更大或更粗 |
| 辅助说明 | 可以弱化，但不能浅到看不清 |
| 按钮文字 | 在 `240px` 或 `280px` 宽度下仍能识别 |

如果字段太多，优先分组、折叠、后置，不要一路缩小字号。

## 按钮要大，间距要够

PDA 上误触成本高，按钮不能做得太精细。

- 高频按钮高度不小于 `48px`。
- 普通按钮高度不小于 `44px`。
- 图标按钮点击热区不小于 `40px x 40px`。
- 相邻按钮间距不小于 `8px`。
- 危险按钮不要紧贴高频主按钮。

戴手套、单手操作、边走边点时，按钮小一点就会明显难用。

## 状态不能只靠颜色

不同 PDA 屏幕差异大，现场光线也复杂。状态只靠颜色不可靠。

更稳的组合是：

```text
颜色 + 明确文字 + 图标或区块 + 下一步动作
```

示例：

```text
成功：已记录，准备扫描下一条
错误：物料不匹配，请重新扫码或上报异常
离线：离线记录中，待补传 2 条
```

按钮置灰时也要说明原因，例如“数量超范围，不能确认”。

## 信息层级要明显

页面不要所有字段都一样重。

| 层级 | 示例 | 视觉处理 |
| --- | --- | --- |
| 第一层 | 当前任务、扫码结果、错误原因、主按钮 | 最明显 |
| 第二层 | 物料名称、规格、数量、差异 | 清楚可读 |
| 第三层 | 备注、操作人、时间、历史 | 弱化或后置 |

不要给每个字段都加边框、阴影、卡片。装饰太多会切碎页面，用户更难扫读。

## 长文本要有规则

PDA 小屏经常遇到长物料名、长单号、长批次号。

- 物料编码优先完整展示。
- 物料名称可以换行，必要时省略后支持查看完整。
- 数量、单位、状态不要被截断。
- 单号过长可以显示关键后缀，但详情里要能看完整。
- 错误原因不能省略到看不懂。

## 固定底栏不要遮挡内容

底部固定按钮适合 PDA，但必须处理遮挡。

- 内容底部预留底栏高度。
- 最后一条记录不能被按钮盖住。
- 输入法弹起时，数量输入和确认按钮仍然可用。
- 底栏和内容之间要有清楚边界。

如果底栏遮住错误提示或最后一行数量，用户会误以为页面没内容。

## 弹层要轻

弹层适合异常上报、选择原因、覆盖确认、查看历史或附件。

在 PDA 上避免：

- 弹层里放复杂表格。
- 弹层套弹层。
- 把主流程放进弹层。

弹层关闭后要恢复扫码焦点，否则用户下一次扫码可能没有反应。

## 小屏和真机检查

至少检查这些宽度：

| 宽度 | 用途 |
| --- | --- |
| `240px` | 极窄设备兜底 |
| `280px` | PDA 主验证宽度 |
| `320px` | 常见 PDA 宽度 |

真机上重点看：

- 当前任务、状态、扫码结果是否一眼可读。
- 主按钮文字是否完整。
- 数量输入是否被输入法遮挡。
- 长物料名是否撑乱布局。
- 强光或低亮度下状态是否还能分辨。
- 戴手套是否能点中高频按钮。

## 检查清单

- 正文是否不小于 `14px`？
- 高频按钮是否不小于 `48px`，点击区间距是否足够？
- 状态是否不只靠颜色表达？
- 关键数量、状态、错误原因是否完整可读？
- 长文本是否不会撑乱布局？
- 固定底栏和输入法是否不遮挡关键内容？
- 是否在 `240px`、`280px`、`320px` 和真实 PDA / HAC WebView 中看过？
