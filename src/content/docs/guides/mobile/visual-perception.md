PDA 页面视觉设计的目标不是漂亮，而是现场人员能快速看懂、准确判断、稳定操作。

仓库、产线、门店后场常见环境是：屏幕小、亮度低、强光反射、设备旧、用户手上忙、可能戴手套。设计稿里看着精致的小字、浅灰色、细边框，到了 PDA 上可能根本看不清。

## 第一眼要看见什么

用户打开页面第一眼要能回答：

```text
我在哪个任务里？
我现在要处理什么？
当前是否正常？
下一步点哪里或扫哪里？
刚才那次有没有成功？
```

如果用户需要上下滚动或仔细读一堆字段才能回答这些问题，首屏就失败了。

## 字号不要太小

建议：

| 内容 | 建议 |
| --- | --- |
| 正文 | 不小于 `14px` |
| 关键数量、状态 | 可以更大或更粗 |
| 辅助说明 | 可以弱化，但不能浅到看不清 |
| 按钮文字 | 要能在 `240px` 或 `280px` 宽度下完整识别 |

不要为了塞更多字段一直缩小字号。字段太多时，应改成分组、折叠、详情，而不是把字变小。

## 按钮要大，间距要够

PDA 上误触成本很高，按钮不能做得太精细。

建议：

- 高频按钮高度不小于 `48px`。
- 普通按钮高度不小于 `44px`。
- 图标按钮点击热区不小于 `40px x 40px`。
- 相邻按钮间距不小于 `8px`。
- 危险按钮不要紧贴高频主按钮。

戴手套、单手操作、边走边点时，按钮小一点就会明显难用。

## 状态不能只靠颜色

PDA 屏幕差异大，现场光线也复杂。状态只靠颜色不可靠。

推荐组合：

```text
颜色 + 明确文字 + 图标或区块 + 处理动作
```

示例：

```text
成功：已记录，准备扫描下一条
错误：物料不匹配，请重新扫码或上报异常
离线：离线记录中，待补传 2 条
```

不推荐：

```text
只把文字变红，不说明原因
只把按钮置灰，不说明为什么不能点
```

## 信息层级要明显

页面不要所有字段都一样重。

推荐层级：

| 层级 | 示例 | 视觉处理 |
| --- | --- | --- |
| 第一层 | 当前任务、扫码结果、错误原因、主按钮 | 最明显 |
| 第二层 | 物料名称、规格、数量、差异 | 清楚可读 |
| 第三层 | 备注、操作人、时间、历史 | 弱化或后置 |

不要每个字段都加边框、阴影、卡片。装饰太多会切碎页面，用户更难扫读。

## 长文本要有处理方式

PDA 小屏经常遇到长物料名、长单号、长批次号。

建议：

- 物料编码优先完整展示。
- 物料名称可以换行，必要时省略后支持查看完整。
- 数量、单位、状态不要被截断。
- 单号过长可以显示关键后缀，但详情里要能查看完整。
- 错误原因不能被省略到看不懂。

## 固定底栏不要遮挡内容

固定底部按钮很适合 PDA，但要处理遮挡。

规则：

- 内容底部预留底栏高度。
- 最后一条记录不能被按钮盖住。
- 输入法弹起时，数量输入和确认按钮仍然可用。
- 底栏和内容之间要有清楚边界。

如果底栏遮住错误提示或最后一行数量，用户会误以为页面没内容。

## 弹层要适合小屏

弹层在 PDA 上要轻。

推荐：

- 弹层只做异常上报、确认、选择、查看历史。
- 弹层内部能滚动。
- 关闭按钮明显。
- 弹层关闭后恢复扫码焦点。

不推荐：

- 弹层里再放复杂表格。
- 弹层嵌套弹层。
- 把主流程放进弹层。

## 小屏验收宽度

PDA 页面至少检查：

| 宽度 | 用途 |
| --- | --- |
| `240px` | 极窄设备兜底 |
| `280px` | PDA 主验证宽度 |
| `320px` | 常见 PDA 宽度 |

重点看：

- 主按钮是否完整。
- 当前任务和状态是否能看清。
- 扫码结果是否明显。
- 数量输入是否被遮挡。
- 错误原因是否完整可读。
- 长物料名是否把布局撑乱。

## 真机上要看这些

不要只看电脑浏览器。

真机检查：

- 目标 PDA 实际视口宽度。
- HAC 或目标 WebView 中的显示。
- 强光或低亮度下是否可读。
- 戴手套是否能点中按钮。
- 连续扫码时状态是否稳定更新。
- 输入法弹起后布局是否乱。

## 视觉说明模板

```text
首屏第一眼：
- 当前任务：
- 当前对象：
- 当前状态：
- 下一步动作：
- 最近结果：

字号：
- 正文：
- 关键数值：
- 按钮：

按钮：
- 主按钮位置：
- 主按钮高度：
- 次按钮：
- 危险操作：

状态：
- 成功：
- 错误：
- 警告：
- 离线：

小屏处理：
- 长名称：
- 长单号：
- 底部按钮遮挡：
- 输入法遮挡：
```

## 检查清单

- 第一眼是否能看出任务、对象、状态、动作和最近结果？
- 正文是否不小于 `14px`？
- 高频按钮是否不小于 `48px`？
- 状态是否不只靠颜色表达？
- 错误原因是否完整可读？
- 长文本是否不会撑乱布局？
- 固定底栏是否不遮挡内容？
- 弹层是否没有承载主流程？
- 是否在 `240px`、`280px`、`320px` 宽度下检查？
- 是否在真实 PDA 或 HAC WebView 中看过？
