PDA 页面好不好用，很大程度取决于交互细节：扫码后有没有反馈，焦点会不会丢，回车会不会触发错动作，失败后能不能继续。

## 扫码是主输入

只要页面用于仓储、物流、生产、巡检等现场作业，就要把扫码当成主输入，而不是把扫码当成普通输入框的附加功能。

推荐流程：

```text
进入页面
-> 自动聚焦扫码入口
-> 用户扫描条码
-> 页面立即显示“校验中”
-> 校验成功，带出数据
-> 自动进入数量输入或下一次扫码
-> 失败时保留码值，显示原因和恢复动作
```

不要让用户每扫一次都先点输入框。

## 焦点规则要写清楚

PDA 连续作业最怕焦点丢失。焦点一丢，用户扫了码，页面没反应，就会以为系统坏了。

推荐规则：

| 场景 | 焦点应该在哪里 |
| --- | --- |
| 页面打开 | 扫码入口 |
| 扫库位成功 | 物料扫码入口 |
| 扫物料成功 | 数量输入框，或直接等待确认 |
| 数量回车确认后 | 提交中禁用输入 |
| 提交成功 | 清空当前记录，回到扫码入口 |
| 提交失败 | 停在需要修改的字段 |
| 弹层关闭 | 回到打开弹层前的焦点 |

这些规则要在页面设计时写出来，不能靠开发临场猜。

## 回车不能乱用

很多扫描头会在条码后自动带回车，所以回车行为必须稳定。

推荐：

- 扫码框回车：触发扫码校验。
- 数量框回车：数量有效时触发确认。
- 提交中回车：忽略，防止重复提交。
- 异常状态回车：优先回到安全动作，例如重新扫码。

不推荐：

- 同一个回车同时触发扫码和提交。
- 提交中回车再次提交。
- 回车触发表单默认跳转。

## 成功后自动继续

连续作业页面，成功后应该自动进入下一条。

示例：

```text
确认收货成功
-> 最近记录新增一条
-> 已收数量 +1
-> 清空当前物料和数量
-> 聚焦扫码入口
-> 提示“请扫描下一件物料”
```

不要成功后只停留在原页面，让用户自己清空、自己点下一条。

## 失败后不要清空

失败时要保留现场数据，因为用户可能还需要核对。

推荐：

```text
物料不属于当前收货单
当前码值：M-10086
动作：重新扫码 / 上报异常
```

不推荐：

```text
清空输入框，只提示“操作失败”
```

这样用户不知道刚才扫的是什么，也不知道为什么失败。

## 按钮文案要说人话

按钮要直接说明动作。

推荐：

- 确认收货
- 确认盘点
- 重新扫码
- 上报异常
- 稍后补传
- 覆盖数量

不推荐：

- 确定
- 提交
- 处理
- 下一步
- 操作

PDA 现场人员没有时间猜“确定”到底确定什么。

## 主按钮只有一个

一个页面或一个作业阶段，只保留一个最明显的主按钮。

如果页面同时出现多个同样醒目的按钮，例如：

```text
保存   提交   确认   下一步   完成
```

用户会犹豫，也容易点错。

推荐做法：

- 当前阶段最重要的动作做主按钮。
- 次要动作弱化或放到更多入口。
- 危险动作单独确认。
- 禁用按钮要说明为什么不能点。

## 数量录入要省事

数量输入是 PDA 高频操作，不能做得像普通复杂表单。

推荐：

- 使用数字键盘。
- 默认带出常用值，例如 `1`、账面数量、包装数量。
- 显示单位，例如 `PCS`、`kg`、`箱`。
- 输入时实时显示差异。
- 超范围时立即提示。
- 回车可以确认。

异常时再让用户填备注，正常情况不要强制写长文本。

## 重复扫码要有规则

重复扫码不是简单报错，要看业务含义。

| 重复情况 | 建议 |
| --- | --- |
| 扫描头短时间重复触发 | 防抖，避免重复处理 |
| 同一物料已处理 | 提示已处理，允许查看记录 |
| 需要累计数量 | 合并数量并显示累计结果 |
| 需要覆盖数量 | 要求确认并记录原因 |
| 上一条结果不确定 | 提示先确认状态，避免重复提交 |

关键业务要有防重复提交机制。只禁用前端按钮不够，服务端也要能识别重复。

## 错误提示要告诉下一步

错误提示建议按这个格式写：

```text
发生了什么 + 为什么影响当前任务 + 用户现在可以怎么做
```

示例：

```text
物料不属于当前收货单，请重新扫描物料码或上报异常。
```

```text
网络连接中断，当前记录已暂存。网络恢复后可补传。
```

```text
提交结果暂时无法确认，请刷新状态，不要重复扫描同一箱号。
```

## 交互说明模板

```text
页面打开后：
扫码成功后：
扫码失败后：
数量输入后：
点击主按钮后：
提交成功后：
提交失败后：
重复扫码时：
断网时：
弹层关闭后：
```

把这 10 条写清楚，页面基本不会出现“用户不知道怎么继续”的问题。

## 检查清单

- 页面打开后是否自动聚焦扫码入口？
- 扫码后是否立即反馈？
- 成功后是否自动进入下一条？
- 失败后是否保留码值和输入？
- 回车行为是否唯一且稳定？
- 主按钮是否只有一个，文案是否清楚？
- 数量输入是否支持数字键盘、单位、范围和回车？
- 重复扫码是否有业务规则？
- 提交中是否防重复点击和重复提交？
- 错误提示是否告诉用户下一步？
