PDA 页面设计的第一步，不是画界面，也不是列字段，而是先把页面要解决的现场任务说清楚。

如果这一步没想清楚，后面很容易做成这样：字段很多、按钮很多、看起来功能完整，但仓库人员拿着 PDA 不知道先扫哪里、错了怎么改、成功后下一步去哪。

## 先写一句页面任务

每个 PDA 页面都应该能用一句话说清楚：

```text
谁在什么现场，为了完成什么任务，需要先判断什么，再做什么动作。
```

示例：

```text
仓管员在收货现场使用 PDA 扫描物料，为了完成当前收货单入库，
需要先判断物料是否属于当前收货单，再确认数量并提交，成功后继续扫下一条。
```

这句话能帮你判断页面上哪些内容重要，哪些内容可以后置。

不推荐这样写：

```text
展示收货单信息，支持收货操作。
```

这句话太空。它没有说明谁用、在哪里用、先判断什么、成功后怎么继续。

## 先确认使用现场

PDA 页面必须按真实现场设计。办公室里觉得“还能用”的页面，到了仓库和产线可能完全不好用。

设计前至少确认这些信息：

| 信息 | 为什么重要 |
| --- | --- |
| 使用角色 | 仓管员、盘点员、巡检员、生产人员的操作习惯不同 |
| 作业地点 | 仓库、门店、产线、户外的光线、网络和噪声不同 |
| 设备型号 | 不同 PDA 的屏幕宽度、WebView、扫码能力差异很大 |
| 是否使用 HAC | 决定是否能调用扫码、定位、离线存储等能力 |
| 扫码方式 | 摄像头、扫描头、UHF、广播模式的交互不一样 |
| 网络条件 | 决定是否要本地暂存、补传和结果确认 |
| 作业频率 | 偶尔查一次和连续扫几百条，页面结构完全不同 |

## 区分三类页面

不要把所有 PDA 页面都做成“列表 + 详情 + 表单”。先判断它属于哪一类。

| 页面类型 | 适合场景 | 设计重点 |
| --- | --- | --- |
| 连续作业页 | 收货、盘点、出库、复核、报工 | 扫码快、自动聚焦、成功后下一条 |
| 任务选择页 | 选择盘点单、拣货任务、巡检路线 | 少筛选、状态清楚、快速进入任务 |
| 异常处理页 | 数量差异、破损、物料不匹配 | 原因清楚、保留现场数据、能上报 |

多数 PDA 业务会由这三类页面组合而成：

```text
任务选择页 -> 连续作业页 -> 异常处理页 / 记录查询页
```

## 主流程要短

PDA 现场操作越短越好。连续作业页面尤其要避免来回跳转。

推荐流程：

```text
进入任务 -> 扫码 -> 校验 -> 输入数量 -> 确认 -> 自动准备下一条
```

不推荐流程：

```text
进入列表 -> 打开详情 -> 扫码 -> 填表 -> 弹窗确认 -> 返回列表 -> 再打开下一条
```

后者每条记录都让用户停顿，处理几十条、几百条时会非常慢。

## 异常流程也要提前设计

只设计正常流程是不够的。PDA 现场最常见的问题包括：

- 扫错码
- 物料不属于当前任务
- 数量超范围
- 同一条码重复扫描
- 当前单据已被别人处理
- 网络断开
- 提交超时，不知道有没有成功
- PDA 扫码广播没有进入页面

每种异常都要给用户一个明确动作：

| 异常 | 用户应该能做什么 |
| --- | --- |
| 扫错码 | 重新扫码 |
| 物料不匹配 | 查看原因、重扫、上报异常 |
| 数量错误 | 修改数量 |
| 重复扫码 | 查看已处理记录、按权限覆盖 |
| 网络断开 | 本地暂存、稍后补传 |
| 提交结果不确定 | 刷新状态，不要盲目重复提交 |

## 成功后要自动进入下一步

PDA 页面经常用于连续作业。成功后不要让用户停在原地猜下一步。

常见成功路径：

| 场景 | 成功后行为 |
| --- | --- |
| 收货 | 清空当前物料，聚焦扫码入口 |
| 盘点 | 最近记录新增一条，等待下一次扫码 |
| 出库复核 | 更新已复核数量，继续扫下一箱 |
| 巡检 | 进入下一个检查项或返回任务列表 |
| 异常上报 | 显示上报编号，返回原作业页 |

## 页面说明模板

开始做页面前，先把这段补齐：

```text
页面名称：
页面类型：连续作业页 / 任务选择页 / 异常处理页 / 查询页
主要用户：
使用现场：
目标设备：
是否使用 HAC：
主要输入方式：扫码 / 物理按键 / 数字键盘 / 触屏

一句话任务：

主流程：
1.
2.
3.

异常流程：
- 扫错：
- 重复：
- 业务不匹配：
- 网络失败：
- 提交结果不确定：

成功后：

验收标准：
```

## 最低验收标准

页面设计完成后，至少要满足：

- 用户能在首屏知道当前任务是什么。
- 用户知道现在应该扫什么或填什么。
- 成功后页面自动准备下一条。
- 失败后保留当前输入，并告诉用户怎么恢复。
- 弱网或断网时不丢关键数据。
- 在目标 PDA 上完成真实流程验证。

## 检查清单

- 是否写出了一句话任务？
- 是否确认了真实 PDA、网络、扫码方式和 HAC 环境？
- 是否区分了主流程和异常流程？
- 是否设计了成功后的下一步？
- 是否避免把连续作业做成反复进出详情页？
- 是否有明确的真机验收标准？
