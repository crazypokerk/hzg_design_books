## 场景概述

这个案例演示如何基于移动端设计手册，从一个真实的 `PDA` 需求场景出发，逐步推导出最终可使用的页面。

场景选择“仓库库存盘点”。它是典型 `PDA` 高频作业场景，用户需要在仓库货架前连续扫码、录入数量、处理异常，并且经常遇到弱网、扫码失败、物料不匹配、数量差异等问题。

```text
页面名称：PDA盘点扫码
主要用户：仓库盘点员
使用场景：仓库货架前，手持PDA连续扫描库位和物料
使用设备：PDA HAC
最小验证宽度：280px ，兼容 240px 和 320px
核心任务：确认当前库位下的物料实盘数量，并持续完成下一条盘点记录
```

这个页面的目标不是展示完整库存资料，而是让盘点员在现场快速完成一条又一条盘点记录。

## 第一步：目标与场景

设计开始前，先把用户、环境、设备和任务成功标准写清楚。

### 用户和现场环境

```text
用户：仓库盘点员
工作方式：站在货架前，单手或双手持 PDA，连续扫描库位码和物料码
输入方式：扫码枪输入为主，数字键盘录入数量为辅
网络环境：仓库局部弱网，可能短时间断网
现场风险：扫错库位、扫错物料、数量录错、网络失败后重复提交
用户最怕：已扫记录丢失、异常原因不清楚、需要反复返回列表重新进入
```

### 页面任务句

> 盘点员在仓库盘点现场，为了完成当前盘点任务，需要先确认库位和物料是否匹配，再录入实盘数量并提交，成功后自动进入下一次扫码；失败时保留当前记录并给出可恢复动作。

这个任务句决定了页面不能做成普通“详情页 + 表单提交”。它需要支持连续作业、自动聚焦、即时反馈和失败恢复。

### 流程设计

```text
主流程：
进入盘点任务 -> 扫描库位 -> 扫描物料 -> 系统校验匹配
-> 带出账面数量和物料信息 -> 输入实盘数量 -> 确认盘点
-> 成功记录 -> 自动清空输入并聚焦下一次扫码

异常流程：
库位不属于当前任务 -> 显示原因 -> 重新扫码 / 切换任务
物料不在当前库位 -> 显示原因 -> 重新扫码 / 上报异常
实盘数量超过合理范围 -> 提示可接受范围 -> 修改数量 / 确认异常
重复扫描同一物料 -> 提示已盘点 -> 查看记录 / 覆盖数量

中断恢复：
网络断开 -> 本地暂存已扫记录 -> 显示待补传数量
提交超时 -> 保留当前记录 -> 刷新状态 / 重试提交
退出后返回 -> 恢复当前任务、库位、待补传队列和最近记录
```

### 成功标准

```text
- 首屏能看到当前任务、库位、进度、扫码入口和最近一次结果
- 扫码后 1 秒内给出成功或失败反馈
- 成功后自动准备下一次扫码，不要求用户反复点击返回
- 失败后保留当前输入，并告诉用户原因和下一步动作
- 断网时不丢已扫记录，网络恢复后可补传
- 在 280px PDA 宽度下，主操作、状态和数量输入仍可用
```

## 第二步：信息架构

信息架构的重点是决定用户先看什么、先做什么、哪些信息后置。

### 首屏判断

盘点员打开页面后，第一眼需要完成五个判断：

```text
对象：当前盘点任务和当前库位
状态：在线 / 离线、盘点中 / 已完成 / 有异常
关键数值：已盘数量 / 应盘数量、待补传数量
风险提示：库位错误、物料不匹配、数量差异
主操作：扫描或确认盘点
```

### 内容分组

```text
第一组：任务摘要
- 盘点单号
- 当前库位
- 已盘 / 应盘
- 在线状态和待补传数量

第二组：扫码作业区
- 当前扫码输入框
- 扫码类型提示：先扫库位 / 再扫物料
- 最近一次扫码结果

第三组：物料与数量
- 物料编码、物料名称、规格
- 账面数量
- 实盘数量输入
- 差异数量

第四组：异常与恢复
- 异常原因
- 处理动作：重新扫码、覆盖数量、上报异常、稍后补传

第五组：最近记录
- 最近 3 条已盘记录
- 完整历史后置到“查看记录”
```

### 页面结构选择

这个需求适合“连续作业页”，不适合“列表到详情”结构。

```text
推荐结构：
单页连续作业
-> 首屏固定任务摘要和扫码区
-> 中部展示当前物料和数量
-> 底部固定主操作
-> 异常、历史和任务切换放到轻量入口

不推荐结构：
盘点任务列表 -> 物料详情 -> 数量表单 -> 提交 -> 返回列表 -> 再打开下一条
```

原因很直接：`PDA` 现场作业的效率来自连续处理。每条记录都返回列表，会显著增加停顿和误操作。

## 第三步：交互与行为

交互设计需要把每一次扫码、输入、提交、失败恢复定义清楚。

### 行为路径

```text
进入页面：
显示当前盘点任务 -> 自动聚焦扫码输入框 -> 等待扫描库位

扫描库位：
收到条码 -> 显示“校验库位中” -> 校验成功后锁定当前库位
-> 扫码提示切换为“请扫描物料码”

扫描物料：
收到条码 -> 显示“校验物料中” -> 校验成功后带出物料信息
-> 自动聚焦实盘数量

输入数量：
用户输入数量 -> 回车或点击“确认盘点” -> 本地校验数量格式
-> 提交或进入本地待补传队列

成功后：
显示成功结果 -> 最近记录新增一条 -> 已盘数量 +1
-> 清空物料和数量 -> 聚焦扫码输入框 -> 等待下一次扫描

失败后：
停留当前记录 -> 显示失败原因和处理动作
-> 用户重新扫码、修改数量、上报异常或稍后补传
```

### 操作层级

```text
主操作：
- 未扫物料时：继续扫码
- 已扫物料且数量有效时：确认盘点
- 提交中：提交中，不允许重复点击

次操作：
- 重新扫码
- 查看记录
- 切换库位
- 上报异常

危险操作：
- 清空当前记录
- 覆盖已盘数量
```

按钮文案要说明具体动作，不使用“确定”“处理”这类含糊文案。

```text
推荐：
确认盘点
重新扫码
上报异常
覆盖数量
稍后补传

不推荐：
确定
提交
处理
下一步
```

### 表单和输入规则

```text
扫码输入：
- 页面进入后自动聚焦
- 支持扫码枪回车触发校验
- 扫码成功后自动进入下一字段
- 扫码失败后不清空错误码，便于用户核对

实盘数量：
- 使用数字键盘
- 默认带出 1 或账面数量，由业务规则决定
- 支持回车确认
- 允许小数时显示单位和精度要求
- 数量为空、负数、格式错误时阻断提交

备注：
- 默认折叠
- 只有上报异常、覆盖数量、差异超阈值时要求填写
```

### 状态反馈

关键错误不能只用短暂提示。页面内必须保留原因和恢复动作。

| 场景 | 页面反馈 | 用户动作 |
| --- | --- | --- |
| 库位校验中 | 扫码区显示“校验库位中” | 等待 |
| 物料匹配成功 | 状态条显示“物料匹配成功” | 输入数量 |
| 物料不匹配 | 错误区显示原因 | 重新扫码 / 上报异常 |
| 数量超范围 | 数量字段下方提示范围 | 修改数量 / 确认异常 |
| 网络断开 | 顶部显示“离线记录中，待补传 N 条” | 继续扫码 |
| 提交超时 | 当前记录保留，显示“结果待确认” | 刷新状态 / 重试 |
| 提交成功 | 最近记录新增，页面准备下一次扫码 | 继续作业 |

### 错误文案

```text
物料不匹配：
物料不属于当前库位，请重新扫描物料码或上报异常。

数量超范围：
实盘数量超过允许范围，请修改数量；如现场确认为异常，请上报异常。

网络中断：
网络连接中断，当前记录已暂存到本地。网络恢复后可自动补传。

提交结果待确认：
提交结果暂时无法确认，请刷新状态，不要重复扫描同一物料。

重复盘点：
该物料已完成盘点。你可以查看记录，或填写原因后覆盖数量。
```

## 第四步：视觉与感知

这个页面的视觉目标不是精致装饰，而是让盘点员在小屏、强光和连续操作中快速判断状态。

### 首屏视觉目标

```text
第一眼看到：
- 当前任务和库位
- 在线 / 离线状态
- 已盘 / 应盘进度
- 扫码输入区
- 最近一次扫码结果
- 当前主操作
```

### 视觉层级

```text
第一层：
扫码结果、错误原因、确认盘点按钮、当前库位、在线状态

第二层：
物料名称、规格、账面数量、实盘数量、差异

第三层：
盘点单号、操作人、最近记录、备注、历史
```

### 固定区域

```text
顶部固定区：
- 页面标题
- 在线 / 离线状态
- 待补传数量

底部固定区：
- 左侧次操作：重新扫码
- 右侧主操作：确认盘点
- 高度不低于 48px
- 内容区底部预留底栏高度，避免最后一条记录被遮挡

弹层：
- 只用于异常上报、覆盖确认、查看完整记录
- 弹层内部可滚动
- 不承载完整盘点流程
```

### 状态表达

状态不只依赖颜色，要组合使用文字、位置、背景区块和动作。

```text
成功：
状态文案：匹配成功，已记录
视觉处理：成功状态条 + 最近记录新增 + 自动聚焦下一次扫码

警告：
状态文案：数量存在差异
视觉处理：差异数值突出 + 显示上报异常入口

错误：
状态文案：物料不属于当前库位
视觉处理：错误区块固定在扫码区下方 + 重新扫码 / 上报异常

离线：
状态文案：离线记录中，待补传 2 条
视觉处理：顶部状态常驻 + 不阻断继续扫码
```

## 第五步：性能与真实环境

`PDA` 页面必须优先保证连续作业不中断。

### 首屏加载

```text
首屏必须加载：
- 当前盘点任务
- 当前库位
- 已盘 / 应盘数量
- 本地待补传数量
- 扫码输入状态

可以延后加载：
- 完整盘点明细
- 历史记录
- 操作日志
- 附件和图片
```

### 数据策略

```text
任务摘要接口：
只返回任务号、库位、进度、状态和权限。

物料校验接口：
扫码后按库位和物料码校验，只返回当前物料所需字段。

提交接口：
使用幂等键，避免重复提交产生重复盘点记录。

本地暂存：
断网时保存库位、物料、数量、时间、操作人和本地记录 ID。

补传队列：
网络恢复后按顺序补传，失败时保留原因和重试入口。
```

### 响应要求

```text
扫码后：
- 立即显示“校验中”
- 1 秒内尽量给出匹配结果
- 超时后允许暂存，不让用户卡在等待中

确认盘点后：
- 按钮进入提交中状态
- 防止重复点击
- 成功后自动清空输入并聚焦扫码框

连续作业：
- 最近记录只展示 3 条
- 完整记录分页或进入独立列表
- 连续处理 200 条记录后页面不明显变慢
```

### 真机验证

```text
最小宽度：
- 240px：确认信息是否被截断
- 280px：主验证宽度
- 320px：常见 PDA 宽度

设备环境：
- 目标 PDA WebView
- 旧安卓 WebView
- 仓库弱网环境
- 扫码枪回车输入

验证动作：
- 连续扫码 50 次
- 断网后扫码 10 条，再恢复网络补传
- 重复扫描同一物料
- 输入法弹起后修改数量
- 提交超时后刷新状态
```

## 最终页面方案

### 页面模块

```text
模块一：任务状态栏
用途：让用户确认当前任务、库位、进度和网络状态。
字段：盘点单号、库位、已盘 / 应盘、在线状态、待补传数量。

模块二：扫码作业区
用途：承接扫码枪输入，并显示当前扫码阶段。
字段：扫码输入框、扫码类型提示、校验中状态、最近扫码结果。

模块三：当前物料区
用途：让用户确认扫码结果并录入数量。
字段：物料编码、物料名称、规格、单位、账面数量、实盘数量、差异。

模块四：异常恢复区
用途：在失败时说明原因并提供动作。
动作：重新扫码、修改数量、上报异常、覆盖数量、稍后补传。

模块五：最近记录区
用途：给用户确认刚才是否记录成功。
字段：最近 3 条物料、数量、上传状态。

模块六：底部操作栏
用途：稳定承载高频操作。
按钮：重新扫码、确认盘点。
```

### 页面状态

```text
初始状态：
- 聚焦扫码输入框
- 主操作不可用或显示“等待扫码”

库位已确认：
- 显示当前库位
- 提示“请扫描物料码”

物料已匹配：
- 显示物料信息
- 聚焦实盘数量
- 主操作变为“确认盘点”

提交中：
- 主按钮显示“提交中”
- 禁止重复提交

成功：
- 最近记录新增
- 进度更新
- 清空当前物料和数量
- 聚焦扫码输入框

失败：
- 保留当前输入
- 显示原因和恢复动作
- 不自动跳转

离线：
- 顶部显示待补传数量
- 允许继续扫码
- 记录进入本地队列
```

### 字段和控件规格

| 区域 | 内容 | 控件建议 |
| --- | --- | --- |
| 任务状态栏 | 盘点单号、库位、进度、网络状态 | 固定顶部摘要 |
| 扫码作业区 | 条码输入、阶段提示 | 大输入框，自动聚焦，支持回车 |
| 当前物料区 | 编码、名称、规格、单位 | 字段组，长名称换行 |
| 数量区 | 账面数量、实盘数量、差异 | 数字输入，差异实时计算 |
| 异常区 | 错误原因和动作 | 页面内状态区，不只用 Toast |
| 最近记录 | 最近 3 条记录 | 紧凑列表，更多进入详情 |
| 底部操作 | 重新扫码、确认盘点 | 固定底栏，按钮高度不低于 48px |

### 可交付页面说明

```text
页面名称：
PDA 盘点扫码

页面定位：
面向仓库盘点员的连续扫码作业页。

首屏目标：
确认当前任务和库位，完成扫码、数量录入和盘点确认。

核心交互：
扫码枪输入 -> 自动校验 -> 数量录入 -> 回车或按钮确认 -> 自动进入下一条。

关键恢复：
扫码失败可重新扫码或上报异常；网络失败时本地暂存并进入补传队列。

性能底线：
首屏只加载任务摘要；扫码后立即反馈；连续 200 条记录不卡顿；断网不丢数据。
```

## 评审清单

用下面清单评审最终页面是否符合手册要求。

```text
目标与场景：
- 是否明确主要用户是盘点员？
- 是否明确 PDA WebView、扫码枪、弱网和连续作业？
- 是否定义了任务成功标准？

信息架构：
- 首屏是否能看到任务、库位、进度、扫码入口和主操作？
- 低频信息是否后置？
- 是否避免了列表到详情的慢流程？

交互与行为：
- 扫码、校验、输入、提交、成功、失败是否都有明确路径？
- 主操作是否只有一个？
- 失败后是否保留当前输入？
```
