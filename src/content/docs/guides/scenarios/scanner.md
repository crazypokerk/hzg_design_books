## 功能介绍

扫描功能用于在 `HAC` 中接收 PDA 硬件扫描头返回的结果，并把条码或 RFID 标签编号交给活字格页面继续处理。

这里的扫描主要分两类：

- 激光 / 二维扫描头：读取条码、二维码，适合收货、盘点、拣货、工序报工等“对准一个码”的操作。
- UHF（RFID）扫描器：读取 RFID 标签的 EPC 段，适合批量识别货箱、托盘、资产或工装夹具。

这些能力依赖 PDA 硬件和 Android 容器，不是普通手机浏览器能力。手机没有对应扫描头时，不能用这些命令模拟激光扫码或 UHF 读卡。

## 先了解 UHF

`UHF` 是超高频 RFID。它和常见扫码不一样：扫码需要对准条码或二维码；UHF 通过无线射频读取 RFID 标签，可以在一定距离内一次读到多个标签。

常见特点：

| 项目 | 激光 / 二维扫描头 | UHF / RFID |
| --- | --- | --- |
| 读取对象 | 条码、二维码 | RFID 标签 |
| 操作方式 | 对准一个码扫描 | 按下读卡键后批量读取 |
| 返回内容 | 条码文本 | EPC 段 |
| 典型场景 | 单件确认、单箱收货、工序报工 | 批量盘点、托盘识别、资产巡检 |
| 风险点 | 扫错码、重复扫码、焦点处理 | 一次读到多个标签、读距和环境干扰 |

UHF 的读距、读到的标签数量和稳定性，受设备功率、天线方向、标签位置、金属环境和现场干扰影响很大。页面设计时不要假设每次只会返回一个 EPC。

## 使用前提

使用扫描头相关命令前，需要先确认：

- 应用运行在支持硬件能力的 Android 容器中，例如 `HAC`。
- PDA 设备带有对应硬件：激光 / 二维扫描头，或 UHF（RFID）扫描器。
- PDA 扫描模式设置为“广播”或“Intent”。
- APP 中的“扫描头配置”或“UHF配置”与设备实际配置一致。
- 页面已设计好扫码成功、扫码为空、重复扫码、扫码不匹配和设备未配置时的处理方式。

:::caution[重要]
如果扫描结果与预期不符，先检查 PDA 系统扫描配置和 APP 配置是否一致。很多 PDA 会在系统层面对扫描结果做前后缀、编码、回车、分隔符等预处理；这类问题通常需要和设备厂商确认。
:::

## 命令汇总

| 命令 | 类型 | 硬件要求 | 返回 / 触发方式 |
| --- | --- | --- | --- |
| 【开始持续扫码】 | 异步 | PDA 激光 / 二维扫描头 | 每次按下扫码键后调用子命令 |
| 【停止持续扫码】 | 同步或普通命令 | PDA 激光 / 二维扫描头 | 取消持续接收扫码结果 |
| 【单次扫码】 | 异步 | PDA 激光 / 二维扫描头 | 扫到一次结果后返回 |
| 【开始接收UHF扫描结果】 | 异步 | PDA UHF 扫描器 | 每次读卡后调用子命令 |
| 【停止接收UHF扫描结果】 | 同步或普通命令 | PDA UHF 扫描器 | 停止接收 UHF 结果 |

持续类命令更适合连续作业页；单次扫码更适合弹出式确认或低频操作。

## 开始持续扫码

【开始持续扫码】是异步命令，需要配合 PDA 的激光 / 二维扫描头使用，不能用在普通手机上。

使用前需要确保：

- PDA 扫描模式为“广播”或“Intent”。
- APP 的“扫描头配置”与设备保持一致。
- 当前页面已经准备好接收连续扫码结果。

命令启动后，每次按下扫码键，APP 都会把扫码结果作为参数调用子命令。多次扫描结果之间用半角逗号分隔。

`1.21` 版本后，连续扫码时支持同步返回当次扫码结果。这样页面可以在每次扫码后立即显示“本次扫到什么”，再执行后续校验。

推荐流程：

```text
进入连续作业页
-> 执行【开始持续扫码】
-> 用户按下扫码键
-> APP 接收扫码结果
-> 将扫码结果作为参数调用子命令
-> 页面校验条码是否属于当前任务
-> 成功后清空当前输入，继续等待下一次扫码
```

持续扫码适合收货、盘点、拣货这类高频操作。页面要特别处理重复扫码、连续扫码过快和扫码结果为空的情况。

## 停止持续扫码

【停止持续扫码】用于取消持续扫码功能。执行后，用户再按下扫码键时，APP 不再处理扫描头返回的结果。

建议在这些场景执行停止命令：

- 离开连续作业页。
- 打开弹窗、拍照、签名等会打断扫码流程的操作。
- 当前任务已完成，不再需要继续接收扫码。
- 页面切换到只读、查询或异常处理状态。

如果没有及时停止持续扫码，用户在其他页面按下扫码键时，可能会误触发旧页面的子命令。

## 单次扫码

【单次扫码】是异步命令，需要配合 PDA 的激光 / 二维扫描头使用，不能用在普通手机上。

使用前同样需要确保：

- PDA 扫描模式为“广播”或“Intent”。
- APP 的“扫描头配置”与设备保持一致。

单次扫码提供两种体验：

| 模式 | 表现 | 适用场景 |
| --- | --- | --- |
| 模态 | APP 弹出固定界面，遮住当前页面，直到扫码完成 | 必须完成扫码才能继续的确认动作 |
| 非模态 | 当前页面保持可用，扫码在后台等待结果 | 页面上仍需要查看或编辑信息的操作 |

推荐流程：

```text
点击“扫码”
-> 执行【单次扫码】
-> 扫码成功后返回码值
-> 写入变量或单元格
-> 按业务规则校验
-> 成功进入下一步，失败保留码值并提示原因
```

如果页面已经是连续作业页，通常优先使用【开始持续扫码】。如果只是偶尔扫一次，例如绑定设备、确认箱号、选择单据，可以使用【单次扫码】。

## 开始接收 UHF 扫描结果

【开始接收UHF扫描结果】是异步命令，需要配合 PDA 的 UHF（RFID）扫描器使用，不能用在普通手机上。

使用前需要确保：

- PDA UHF 扫描模式为“广播”或“Intent”。
- APP 的“UHF配置”与设备保持一致。
- 业务页面可以处理一次返回多个 EPC 的情况。

命令启动后，每次按下读卡键或扳机，APP 都会把读卡结果作为参数调用子命令。返回内容通常是 RFID 标签的 `EPC` 段；如果一次扫描到多个 RFID 标签，EPC 之间用半角逗号分隔。

推荐流程：

```text
进入 UHF 盘点页
-> 执行【开始接收UHF扫描结果】
-> 用户按下读卡键 / 扳机
-> APP 接收一个或多个 EPC
-> 去重、拆分并写入本次扫描列表
-> 根据 EPC 查询业务对象
-> 显示已识别、未匹配和重复标签
```

UHF 场景不要只显示一个“扫码结果”输入框。更合适的页面是“本次读取列表 + 已匹配数量 + 未匹配原因 + 清空 / 重新读取 / 提交”。

## 停止接收 UHF 扫描结果

【停止接收UHF扫描结果】用于停止接收来自 UHF 扫描器的结果。

建议在这些场景执行：

- 离开 UHF 作业页。
- 当前批次读取完成并已提交。
- 页面进入异常处理、拍照、签名或确认弹窗。
- 需要切换到普通激光扫码流程。

停止后，读卡键或扳机不再触发 APP 的 UHF 子命令处理。

## 页面设计建议

扫描类页面要把“当前正在扫什么”讲清楚。

- 页面顶部显示当前任务、单据、库位、工位或批次。
- 扫码区显示等待扫码、扫码中、扫码成功、扫码失败等状态。
- 激光扫码结果要保留原始码值，便于排查设备前后缀或编码问题。
- 持续扫码页面成功后要自动准备下一次扫码，减少手动点击。
- UHF 页面要显示本次读取 EPC 数量、去重后数量、匹配成功数量和未匹配数量。
- 离开页面、打开弹窗或切换任务时，要停止持续接收。

## 异常处理

| 异常 | 可能原因 | 推荐处理 |
| --- | --- | --- |
| 按扫码键无反应 | PDA 扫描模式不对、APP 配置不匹配、未启动持续扫码 | 提示检查广播 / Intent 配置，并允许重新启动命令 |
| 扫码结果为空 | 条码损坏、距离不合适、扫描头未读到结果 | 保留页面状态，提示重新扫描 |
| 结果带前后缀 | PDA 系统层做了预处理 | 记录原始码值，与设备厂商确认配置 |
| 重复扫码 | 用户连续按键、扫描头重复上报 | 页面去重或提示已扫描 |
| 条码不匹配 | 扫错物料、箱号或任务 | 保留码值，提示不属于当前任务 |
| UHF 一次读到多个 EPC | 读距过远、附近标签较多 | 展示列表，允许清空、去重、提交匹配项 |
| UHF 读不到标签 | 标签方向、距离、金属环境、功率设置影响 | 提示调整位置或检查设备功率 |

## 验收标准

一个扫描页面至少应满足以下标准：

1. PDA 扫描模式和 APP 扫描配置一致，激光扫码或 UHF 读卡能触发页面命令。
2. 持续扫码页面在离开时会执行停止命令，不影响其他页面。
3. 单次扫码能区分模态和非模态体验，并能处理取消或失败。
4. UHF 返回多个 EPC 时，页面能拆分、去重、匹配并展示异常项。
5. 页面记录原始扫描结果，便于排查设备预处理和现场问题。
