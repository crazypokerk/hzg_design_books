活字格安卓容器（HAC）是一个内置 `WebView` 的 Android 原生应用。如果 HAC 中出现页面白屏、样式异常、按钮无响应、接口请求失败、扫码结果没有写入页面等问题，可以先通过 `Chrome DevTools` 查看页面运行时状态。

这种方式适合排查前端脚本报错、资源加载失败、接口异常、缓存异常和移动端布局问题。

## 调试前准备

- 一台已安装 `Chrome` 浏览器的电脑
- 一台安装了 `HAC` 的 Android 手机或 PDA
- 一根可传输数据的 `USB` 线
- HAC 中已打开需要调试的活字格页面

如果使用 PDA，建议优先使用原装数据线，并确认电脑已安装设备所需的 USB 驱动。部分设备连接电脑后默认只充电，需要在系统通知中把 USB 用途切换为“文件传输”或类似模式。

## 开启设备调试

1. 打开 Android 设备的“开发者选项”。如果设置中没有该入口，通常可以进入“关于手机”或“关于设备”，连续点击“版本号”若干次启用。
2. 开启“USB 调试”。
3. 如果设备中有“启用视图属性检查功能”或类似选项，也一并开启。
4. 使用 USB 线连接设备和电脑。
5. 设备弹出 USB 调试授权提示时，选择允许。

如果没有弹出授权提示，可以重新插拔 USB 线，或在“开发者选项”中撤销 USB 调试授权后再连接一次。

## 连接 Chrome DevTools

1. 在电脑上打开 Chrome。
2. 在地址栏输入：

   ```text
   chrome://inspect/#devices
   ```

3. 勾选 `Discover USB devices`。
4. 等待 Chrome 识别已连接的 Android 设备。
5. 打开 HAC，并进入需要调试的活字格页面。
6. 在 `Remote Target` 列表中找到对应的 `WebView` 页面，点击 `inspect`。

打开的 DevTools 窗口对应 HAC 中正在运行的页面，可以像调试普通网页一样查看控制台、网络请求、DOM、样式和存储数据。

## 重点检查内容

### Console

优先查看是否有红色错误信息。常见问题包括：

- JavaScript 运行时报错
- 第三方脚本加载失败
- 浏览器能力或 WebView 版本不兼容
- 页面逻辑执行顺序异常

页面按钮无响应、扫码后没有触发后续动作时，也可以先从这里确认是否有脚本错误。

### Network

刷新 HAC 页面后，重点关注：

- 接口是否返回 `401`、`403`、`404`、`500` 等异常状态码
- 静态资源是否加载失败
- 请求地址是否指向正确服务器
- 弱网环境下是否超时
- 请求返回内容是否符合页面预期

如果页面白屏但 `Console` 没有明显错误，通常需要同时检查主文档、脚本文件和接口请求。

### Elements

用于检查页面结构和样式，适合排查：

- 元素存在，但被遮挡或透明
- 弹窗、底部按钮、扫码输入框位置异常
- PDA 小屏宽度下布局溢出
- 样式被其他规则覆盖

PDA 屏幕较窄，调试时需要同时观察设备真实屏幕上的展示。

### Application

如果怀疑缓存、登录态或本地数据有问题，可以查看 `Local Storage`、`Session Storage`、`Cookies` 和缓存数据。遇到旧页面、旧配置或登录态异常时，可以清理相关站点数据后重新打开 HAC 页面。

## 常见问题

### Chrome 看不到设备

先确认 USB 线支持数据传输，并检查设备是否已经开启“USB 调试”。仍然无法识别时，可以尝试：

- 重新插拔 USB 线
- 更换 USB 口或数据线
- 将 USB 用途切换为“文件传输”
- 在设备上重新授权 USB 调试
- 安装或更新设备厂商提供的 USB 驱动

### 能看到设备，但看不到 HAC 页面

确认 HAC 已经打开，并进入实际的活字格页面。`chrome://inspect/#devices` 只会显示当前可调试的 WebView 页面，如果 HAC 仍停留在启动页、配置页或页面尚未加载完成，列表中可能看不到目标页面。可以重启 HAC 后再刷新该页面。

### 点击 inspect 后页面为空或断开

这通常和连接状态、WebView 版本或页面进程有关。保持 HAC 在前台运行后，重新点击 `inspect`。如果设备 WebView 版本过旧，建议在 HAC 设置中查看版本，并联系设备厂商升级系统 WebView。

### 页面在浏览器正常，在 HAC 中异常

这种情况通常与 Android WebView、设备能力或 HAC 运行环境有关。建议检查：

- WebView 版本是否过低
- 是否使用了较新的浏览器 API
- 页面是否依赖桌面端浏览器特性
- PDA 屏幕宽度下是否存在布局溢出
- 接口地址、证书、跨域或内网访问是否在设备上可用

## 调试建议

建议按“错误信息、网络请求、页面结构、本地数据”的顺序排查。先确认是否有明确报错，再确认请求是否成功，最后检查样式、布局和缓存状态。

如果问题只在某一台 PDA 上出现，应记录设备型号、Android 版本、WebView 版本、HAC 版本、网络环境和复现步骤。
