## 业务目标与边界

本示例用于设计 `PDA + HAC + 活字格移动页面 + 硬件扫码头` 下的采购入库流程。页面服务于仓库现场连续收货，不是采购管理后台的缩小版。

| 项目 | 约束与设计输入 |
| --- | --- |
| 主要角色 | 仓库收货员负责连续收货；采购管理员只处理订单异常、超收授权和同步冲突 |
| 作业现场 | 仓库收货区，存在单手或戴手套操作、噪声、强光、连续扫码和弱网情况 |
| 目标设备 | 盈达 `iData 50`，页面按 `240px` 极窄宽度设计，并在 `280px`、`320px` 下复核 |
| 运行环境 | HAC Android 容器；实施前登记 Android、HAC 和 WebView 版本，并完成扫码桥接验证 |
| 扫码方式 | 以 PDA 硬件扫码头和物理扫描键为主，不要求用户先点击输入框 |
| 网络条件 | 在线、弱网和断网；断网期间允许继续收货，本地记录恢复在线后补传 |
| 页面类型 | 首页任务入口、POList 订单选择页、PODetails 连续收货作业页 |
| 范围边界 | 不覆盖供应商管理、价格、对账、财务入账和完整采购审批 |

页面应使用手机端单元格命令，例如 `Vant` 组件、移动端输入框、按钮、标签页和扫码命令。不要直接套用桌面端大表格、大表单和密集按钮布局。

### 术语约定

本案例统一使用以下字段，页面文案、活字格字段和数据库字段不得混用：

| 字段 | 含义 |
| --- | --- |
| `ExpectedQuantity` | PO 应收数量 |
| `ReceivedQuantity` | 已累计收货数量 |
| `ReceiveQuantity` | 本次确认的收货数量 |
| `QualityStatus` | 可选的质量状态，例如合格、待检、不合格；它不是数量字段 |

如果现有数据表使用 `Quantity`，应明确它对应以上哪个数量。原页面中的 `Quality` 若实际表示数量，必须迁移或重命名后再实施。

## 页面流程与职责

| 页面 | 页面任务 | 主操作 | 成功后的下一步 |
| --- | --- | --- | --- |
| Home | 查看当前待办与异常，并进入采购入库 | 扫描 PO 或进入 POList | 打开唯一匹配的 PO；不能唯一匹配时进入 POList 选择 |
| POList | 筛选、扫描和选择一个待收货 PO | 选择 PO | 打开 PODetails |
| PODetails | 对当前 PO 连续扫描物料并确认收货数量 | 确认收货 | 显示上一条结果，恢复扫码状态，继续下一件 |

首页和 POList 只接受 `PO` 条码。PODetails 只接受物料编码或 `EAN`。物料描述仅用于手动搜索，不能作为扫码目标。

## 作业流程

```text
打开 PDA 应用
-> 扫描 PO，或从 POList 选择订单
-> 校验 PO 是否存在、可收货以及当前用户权限
-> 进入 PODetails，显示当前 PO、网络状态和待同步数量
-> 扫描物料编码或 EAN
-> 立即显示码值或“校验中”
-> 校验物料是否属于当前 PO，并带出应收、已收和剩余数量
-> 本次收货数量默认填入 1；按包装扫码时带出包装数量
-> 用户确认或通过数字键盘修改本次收货数量
-> 校验数量范围并确认收货
-> 显示视觉、声音或振动反馈，更新最近一条结果和已收数量
-> 清空当前物料，恢复扫码状态，继续下一件
```

![PDA 连续收货流程示例](../../../assets/mobile-example-receiving-flow.webp)

每个收货循环都在 PODetails 内完成，不通过弹层录入数量，也不要求用户返回列表再打开下一条物料。

## HAC 能力组合

本方案只使用已经在 HAC 功能文档中定义的能力：

- [扫描与 UHF / RFID](../features/scanner/)：接收硬件扫码头结果，处理重复、空码和不匹配；
- [离线模式与本地存储](../features/offline-model-hac/)：断网时暂存必要记录，在线后按业务主键补传；
- [交互行为原则](../principles/interaction-behavior/)：约束焦点、回车、成功反馈和重复操作；
- [性能与稳定性原则](../principles/performance/)：控制首屏数据量、扫码响应和旧 WebView 风险。

这些能力只负责容器桥接或页面设计约束，PO 校验、权限、幂等提交和服务端状态仍由业务页面与服务端负责。

## 页面方案

### Home

首页只显示任务入口和可行动状态，不展示 PO 明细。

| 模块 | 内容 | 设计要求 |
| --- | --- | --- |
| 用户与网络 | 当前用户、角色、在线/离线状态、待同步数量 | 保持常驻且不占用过多首屏高度 |
| 主入口 | 扫描采购订单 | 高度不小于 `56px`；只处理 PO 条码 |
| 任务指标 | 待收货、异常、今日已完成 | 指标可进入相应任务列表，不展示无后续动作的装饰性指标 |
| 功能入口 | 采购入库、移库调拨、盘点任务、库存查询 | 采购入库作为明确主入口，其余入口降级 |
| 底部导航 | 首页、任务、库存、我的 | 不再重复放置“采购入库”，避免同屏出现三个等价入口 |

仓库收货员默认看到个人或当前班次待办；采购管理员可额外看到异常和待授权数量。

### POList

POList 用于快速定位一个 `PO`，不是订单详情页。

| 模块 | 内容 | 设计要求 |
| --- | --- | --- |
| 搜索区 | PO 单号输入框、扫码状态 | 页面打开后即可接收硬件扫码，不要求先点击输入框 |
| 状态筛选 | 待收货、部分收货、已完成 | 默认显示“待收货”；“全部”放入次级筛选 |
| PO 卡片 | PO 编号、状态、供应商、目标仓库、计划到货日期 | 首屏只显示选择订单所需字段；备注、下单日期和完整历史进入详情 |
| 分页 | 每页不超过 `20` 条 | 滚动到底加载下一页，不一次加载全部订单 |

扫码结果规则：

| 场景 | 页面行为 |
| --- | --- |
| 唯一匹配且可收货 | 直接进入 PODetails |
| 唯一匹配但已完成 | 显示“订单已完成”，允许查看只读详情，不进入收货状态 |
| 匹配多条 | 保留当前筛选并显示匹配列表，由用户选择 |
| 无匹配或空码 | 保留码值和列表状态，显示原因，并提供重新扫描 |

### PODetails

PODetails 是连续收货主作业页，应围绕“当前 PO、当前物料、本次数量、上一条结果”组织首屏。

```text
顶部状态区：返回、PO 编号、在线/离线、待同步数量
扫码作业区：扫码状态、当前码值、手动搜索入口
当前物料区：物料编码、名称、规格、应收、已收、剩余
数量区：本次收货数量、单位、数字键盘
最近结果区：上一条物料、数量、成功或失败状态
固定操作区：重新扫描、确认收货
```

设计要求：

- 在线/离线使用可点击的分段控件或开关，触达高度不小于 `44px`，不能使用右上角小文本代替；
- 主作业区一次只突出当前物料，不在长卡片列表中为每条物料重复放置“接收货品”按钮；
- “确认收货”固定在底部，高度不小于 `48px`；内容区必须预留操作栏高度和安全间距；
- 连续收货页不显示全局底部导航，避免遮挡货品内容和误触离开作业；
- 最近一条成功或失败结果保持可见，完整历史进入独立查询页；
- 手动搜索可按物料编码、`EAN` 或物料描述查询；硬件扫码只校验物料编码和 `EAN`。

### 数量校验

| 场景 | 页面行为 |
| --- | --- |
| 本次数量为空、为零或非数字 | 停留在数量输入框，显示允许格式，禁止确认 |
| 本次数量大于剩余数量 | 禁止普通收货；显示剩余数量，并提供采购管理员超收授权入口 |
| 允许小数的计量单位 | 使用数字键盘并限制小数位数；单位为件、箱时只允许整数 |
| 数量有效 | 回车与“确认收货”执行同一动作 |
| 提交中 | 禁用按钮、回车和扫描处理，防止重复提交 |

## 扫码与现场反馈

### 扫码触发

HAC 启动页面时注册扫码监听，退出页面时注销监听。物理扫描键收到码值后直接进入当前页面的校验流程；相机扫码仅作为硬件扫码头不可用时的备用路径，并明确申请相机权限。

| 场景 | 焦点与下一步 |
| --- | --- |
| 进入 Home 或 POList | 等待 PO 扫码 |
| 进入 PODetails | 等待物料扫码 |
| 物料校验成功 | 聚焦本次收货数量；默认值可直接确认 |
| 收货成功 | 清空当前物料并恢复等待扫码 |
| 数量校验失败 | 停留在数量输入框 |
| 提交或同步中 | 暂停处理新的回车和重复提交事件 |

### 反馈规则

| 结果 | 必须反馈 |
| --- | --- |
| 收到码值 | 立即显示码值或“校验中” |
| 扫码成功 | 绿色状态、短提示音或一次振动，并显示物料名称 |
| 校验失败 | 红色状态、不同提示音或两次短振动，保留码值并显示恢复动作 |
| 收货成功 | 更新已收数量和最近结果，提示“请扫描下一件” |
| 网络失败 | 显示已转入本地暂存或结果待确认，不能只显示 Toast |

声音关闭或现场噪声较大时，视觉和振动反馈仍必须可用。

### 重复扫码

- 同一扫码头在 `500ms` 内重复返回相同码值，按硬件抖动忽略；
- 本案例按逐件扫码处理：同一物料再次扫描时累计本次收货数量，并重新执行剩余数量校验；
- 已提交记录不得因重扫 PO 或网络重试而重复创建；前端使用本地记录 ID，服务端执行幂等校验；
- 上一条提交结果不确定时，先查询记录状态，不允许直接再次提交。

## 离线与异常恢复

在线/离线状态必须显式展示。检测到断网时，页面提示用户进入离线作业；恢复在线后自动补传，也保留手动重试入口。

| 状态 | 页面行为 | 数据处理 |
| --- | --- | --- |
| 在线 | 确认后提交服务端 | 成功后更新数量；超时则进入“结果待确认” |
| 离线 | 允许继续收货 | 写入本地队列，显示待同步数量 |
| 恢复在线 | 自动补传 | 显示同步中、成功、失败和冲突数量 |
| 同步失败 | 保留本地记录和失败原因 | 允许重试，不清空用户数据 |
| 版本冲突 | 暂停该记录补传 | 同时显示本地值和服务端值，由采购管理员处理 |

本地记录至少保存：本地记录 ID、PO 编号、物料编码或 `EAN`、原始码值、本次数量、操作人、操作时间、设备型号、服务端基础版本、同步状态和失败原因。

服务端以本地记录 ID 作为幂等键，并校验 `PO + 物料 + 服务端版本`。补传成功后只清理对应记录，不批量清空整个本地队列。

### 异常恢复

| 异常 | 页面动作 |
| --- | --- |
| PO 不存在 | 保留 PO 条码，提示检查订单状态或重新扫描 |
| 物料不属于当前 PO | 保留物料条码，允许重扫或上报异常 |
| PO 已完成 | 切换为只读详情，不默认进入收货动作 |
| 超收 | 显示剩余数量，要求采购管理员授权并记录原因 |
| 本地暂存失败 | 停止继续收货，保留当前输入，提示释放存储空间、重试或联系管理员 |
| 提交超时 | 标记“结果待确认”，允许刷新状态或稍后补传，不提示直接重试 |
| 扫码头无响应 | 提供重新注册监听和相机扫码备用入口，并记录 HAC 日志 |

错误文案统一使用：

```text
发生了什么 + 当前对象 + 现在可以做什么
```

例如：`物料 M-10086 不属于当前采购订单，请重新扫描或上报异常。`

## 方案验收基线

| 项目 | 要求 |
| --- | --- |
| 正文字号 | 不小于 `14px` |
| 高频主按钮 | 高度不小于 `48px` |
| 普通按钮 | 高度不小于 `44px` |
| 图标点击热区 | 不小于 `40px x 40px` |
| 相邻点击区 | 间距不小于 `8px` |
| 状态表达 | 同时使用文字、颜色和必要的图标，不只依赖颜色或感叹号 |
| 长文本 | PO 和物料编码可完整查看；名称允许换行；数量、单位和状态不得截断 |
| 首屏加载 | 先显示任务、PO、网络状态、扫码入口和待同步数量，再延迟加载低频信息 |
| 列表数据 | POList 每页不超过 `20` 条；PODetails 不一次渲染完整 PO 明细 |
| 扫码响应 | 收到码值立即反馈；目标 `1s` 内返回校验结果，超过 `1s` 持续显示处理中 |
| 旧 WebView | 减少动画、阴影、滤镜、深层 DOM 和大列表，避免依赖未经目标设备验证的新能力 |

## 验收标准

1. 在 `240px`、`280px`、`320px` 宽度下无横向滚动，固定操作栏不遮挡最后一条内容，输入法弹起后数量输入和确认按钮仍可用；
2. 使用 iData 50 物理扫描键时，无需先点击输入框即可完成 PO 和物料扫码；
3. 收到条码后立即显示码值或“校验中”；目标在 `1s` 内给出结果，超时后状态持续可见；
4. 正常收货从物料扫码到确认不超过一次额外点击；确认成功后自动恢复到下一次扫码状态；
5. 扫码成功、校验失败、保存成功和网络失败均有视觉反馈，并至少提供声音或振动中的一种；
6. 数量为空、为零、格式错误或超出剩余数量时不能提交；错误附近显示原因和恢复动作；
7. 连续执行 `100` 次扫码和收货操作，无重复记录、焦点丢失、页面明显卡顿或数据丢失；
8. 断网后可继续收货并显示待同步数量；恢复在线后可补传，失败记录保留原因和重试入口；
9. 提交超时后不得直接重复创建记录；刷新或补传能够确认最终状态；
10. Android、HAC、WebView、扫码头型号和权限配置均记录在测试报告中，并在目标真机上通过验证。
