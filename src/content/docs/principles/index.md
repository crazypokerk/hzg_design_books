本部分用于指导页面设计，而不是替代具体功能文档。目标不是把 PC 页面缩小，而是让现场人员在小屏、强光、手套、弱网和高频操作环境中稳定完成当前任务。

## 核心原则

| 原则 | 要求 |
| --- | --- |
| 单一任务焦点 | 每个页面只突出当前阶段最重要的判断和动作 |
| 扫码优先 | 明确扫码触发、焦点、成功反馈、重复处理和异常恢复 |
| 信息分层 | 首屏展示任务、对象、状态、下一步和最近结果 |
| 操作可触达 | 高频按钮和输入区适合单手、戴手套和快速点击 |
| 状态可恢复 | 扫错、断网、超时或重复提交后保留数据并给出恢复动作 |
| 真机验证 | 在目标 PDA、HAC 和 WebView 中验证布局、设备能力和性能 |

## 设计流程

1. [任务与场景定义](./goals-scenarios/)；
2. [信息架构](./information-architecture/)；
3. [交互行为](./interaction-behavior/)；
4. [视觉可读性](./visual-perception/)；
5. [性能与稳定性](./performance/)。

每篇原则都应落到可观察的验收条件，例如扫码反馈时间、最大点击次数、失败恢复路径、弱网补传结果和目标设备表现。
